System Overview & Architecture

The **Food Safety Molecular Analysis Portal** is a production-grade, secure, and decision-support module built upon the shared **ILIMS Core** database. It tracks biological specimens from registration/intake, through molecular isolation and assay execution, to quality review, cryptographic logging, and final safety reporting.

Decision-Support Scope: This software is a data aggregator and analytical interpreter. It records laboratory-confirmed test results and automates compliance reporting; it does not replace wet-lab chemistry or manual diagnostic verification.
Authentication, Security, & Role Matrix

Role-Based Access Control (RBAC)

Users are assigned to one of five roles. Access control is enforced at both the URL router level and the database query/object level.

RolePrimary Authority
TECHNICIANIntake, DNA extractions, batching
ANALYSTPCR/qPCR execution, sequencing, raw results log
QC_OFFICERVerification queue, four-eyes check, safety classification
FOOD_SAFETY_OFFICERReport analysis, global catalog view, alerts consumption
ADMINGeographics, prefixes, feature flags, user management

Hardened Security Architecture

  • 🔒 Argon2id Hashing: Safe from GPU-accelerated brute-force attacks.
  • 🔒 Axes Lockout: Enforces login lockout after 5 failed attempts for 15 minutes.
  • 🔒 Secure serving: Uploaded avatars and generated report PDFs are validated via magic-bytes (preventing execution attacks) and served only through permission-checked views.
  • 🔒 CSP Enforced: Strict Content Security Policies reject all unapproved inline scripts.
  • 🔒 Object Scoping: Technicians and Analysts are strictly isolated to their assigned regional laboratory facility.
Food Specimen Registration & Intake

Interactive registration guide

  1. Navigate to the Intake Samples Directory and select **Register Sample**.
  2. Choose a client using the SmartSelect Type-Ahead input (just start typing to see options).
  3. Enter product details. Selecting a **Product Category** (e.g. Food) automatically unlocks the dependent **Product Types** (e.g. ready-to-eat) cascading options.
  4. Declare the **Molecular Workflow** (DNA Isolation, qPCR, or Sanger Sequencing). The system auto-filters matching laboratory assay methods dynamically.
  5. Set priorities and storage conditions (ambient, chilled, or frozen).
  6. On submission, the system generates a race-safe custom serial code (e.g., FS-LK-WP-2026-00042) and triggers a printable PDF laboratory receipt.

SLA and Deadline Target

SLA timers (Due Dates) are automatically computed at registration using global turnaround limits configured in settings (Normal vs. Urgent timelines), with support for calendar working-day calculations (excluding regional holidays/weekends).

Molecular Laboratory Diagnostics Workflow

Stage 1: DNA Isolation & Purity

Isolate genetic materials from food matrices. Logs method, kit references, and date. Under standard mode, you can capture full purity criteria: **concentration (ng/µL)**, and **A260/280 / A260/230 absorbance ratios** to evaluate extraction quality before PCR runs.

Advances State: received → testing

Stage 2: Assay / PCR & Results Entry

Analysts run molecular tests (qPCR or Sequencing) targeting specific pathogens. Input raw Ct values alongside cutoffs. The platform automatically flags positive detections (e.g., Salmonella target amplification with Ct < 35).

Advances State: testing → analysis
Quality Control & The Four-Eyes Rule
Security Boundary (Four-Eyes Rule): The Analyst or Technician who performed the laboratory test is cryptographically blocked from reviewing and verifying their own results. Another QC Officer must log in to authorize the record.

Upon Molecular Test registration, a pending **QcRecord** is automatically mapped and added to the **QC Queue**. QC Officers inspect the amplification logs, Ct values, and positive targets. They apply a final **Safety Classification** (Safe / Unsafe / Needs Review) and notes.

  • 🟢 Approved (Safe): Specimen advances to **Report Preparation**
  • 🔴 Rejected (Unsafe): Specimen is flagged and moved to **Rejected** state
  • 🔵 Send Back for Rework: Resets state back to **Testing** for rerun extraction
Accreditation Ready
All QC decisions are permanently archived in the **QC Compliance Log**, establishing an audit-ready, exportable checklist required for ISO 17025 laboratory accreditations.
PDF Reports & Deliverables Export

Approved samples undergo final reporting. Clicking **Generate Report** compiles all extraction metrics, amplification Ct values, QC approvals, and pathogen detections into a styled **A4 PDF Document** matching the ILIMS design spec.

The 6 Mandatory Regulatory Deliverables

1. Food Safety Report (PDF)
A4 printable document served from a protected path for secure client delivery.
2. Molecular Test Summary
Interactive detail view showing extraction records, instrument runs, and operator timelines.
3. Pathogen Detection Log
Cross-sample directory showing positive targets and raw Ct amplifications.
4. Batch Traceability Report
Grouping of samples by production batch to trace raw materials contamination back to source suppliers.
5. QC Compliance Log
Chronological timeline of reviewer decisions, notes, and approval timestamps.
6. Audit Trail Export (CSV)
Export the full hash-chained audit log as a CSV for security auditors.
Immutable SHA-256 Chained Audit Trail

Every database write, status advancement, QC review, PDF generation, or CSV export records an entry to the shared **ILIMS Audit Log**. Each record is bound using an **append-only SHA-256 hash-chaining structure** similar to a blockchain ledger.

How the Hash Chain Works:
For any record $N$: Hash = SHA-256( Hash(N-1) + Timestamp + User + Action + Model + RecordID + ChangesJSON )
If any database row is altered, deleted, or inserted out of order, the chain signature breaks!

Hash Verification Console

Clicking **Verify Hash Chain** inside the Audit Log View executes a real-time integrity check, recalculating the expected hashes sequentially from genesis to detect any database tampering.
